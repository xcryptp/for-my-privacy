# For My Privacy — 사이트 잠금 크롬 확장 설계

> 작성 2026-11-13 · 상태: 진행 승인(사용자: "개발하면서 직접 확인하자", 2026-11-13) · 레포를 만들면 `docs/superpowers/specs/2026-11-13-site-lock-design.md`로 옮겨 커밋한다

- 제품 이름: For My Privacy(사용자 지정)
- 스토어와 매니페스트 표시 이름(설계자 판단): `name`은 "For My Privacy: Site Password Lock"(한국어는 "For My Privacy: 사이트 비밀번호 잠금"), `short_name`은 "For My Privacy". 스토어 검색에 걸리도록 하는 일이 무엇인지 이름에 함께 적는다.
- 레포: GitHub `for-my-privacy`(공개). 이슈 레포 코드는 `FMP`(첫 이슈를 열 때 이슈 표기 규칙의 레포 코드 목록에 추가)

## 1. [참고] 목적

- 자리를 비운 사이 다른 사람이 로그인된 내 크롬에서 인스타그램 같은 지정 사이트를 보는 것을 막는다(사용자 답: 막으려는 상황 A).
- 맥과 윈도우의 크롬 데스크톱에서 쓴다.
- 크롬 웹스토어에 올릴 수 있는 상태까지 만들고, MIT 오픈소스로 GitHub에 공개한다. 릴리스마다 버전을 올린다(사용자 지시).

## 2. [확인] 목표 · 비목표 · 실패 조건

2-1. 목표
- 지정한 도메인과 그 모든 서브도메인에 들어가면 사이트 대신 잠금 화면이 뜬다.
- 비밀번호 하나로 잠긴 도메인 전체가 풀린다(설계자 판단).
- 비밀번호는 PBKDF2 해시로만 저장한다. 코드나 저장소를 봐도 원문은 나오지 않는다.
- 풀린 뒤에는 쓰는 동안 계속 열려 있고, 다음 중 하나가 생기면 다시 잠긴다.
  - 컴퓨터 전체에 N분 동안 키보드·마우스 입력이 없을 때(N은 설정, 기본 5분)
  - 화면이 잠길 때(즉시, 설정에서 끌 수 있음)
  - 브라우저를 다시 켤 때
  - 크롬 창을 모두 닫을 때(설계자 판단: 맥은 창을 다 닫아도 크롬이 꺼지지 않으므로)
- 다시 잠길 때 열려 있던 해당 사이트 탭도 잠금 화면으로 바뀌고, 뒤로 가기로 원래 화면이 다시 보이지 않는다.
- 설정 화면도 같은 비밀번호로 잠긴다.
- 확장 관리 화면(`chrome://extensions`) 보호: 잠긴 상태에서 이 화면을 열면 잠금 화면으로 바뀐다. 설정에서 켜고 끌 수 있고 기본은 켜짐이다.
- 화면 언어는 한국어·영어·일본어다(일본어는 README 3개 언어에 맞춘 설계자 판단).

2-2. 비목표
- 자기 절제 기능(하루 사용 한도, 시간대 차단)
- 다른 브라우저, 모바일, 인스타그램 앱
- 시크릿 창과 게스트 모드 차단: 여기에는 내 로그인이 없어서 이 제품이 막으려는 상황이 아니다.
- 비밀번호 복구: 잊으면 확장을 다시 설치해 초기화한다.
- 여러 기기 간 설정 동기화

2-3. 실패 조건(동작해도 실패로 본다)
- 잠긴 상태에서 사이트 내용이 잠깐이라도 보인다.
- 비밀번호 원문이나 쉽게 되돌릴 수 있는 값이 저장된다.
- 데이터가 밖으로 나간다.
- 지정하지 않은 사이트가 막힌다(예: `instagram.com`을 지정했는데 `notinstagram.com`이 막힘).

## 3. [확인] 제약

- 크롬 Manifest V3, 크롬 데스크톱(맥·윈도우).
- 웹스토어 정책: 최소 권한, 단일 목적, 개인정보처리방침 필요, 원격 코드 금지, 난독화 금지.
- 공개 코드라서 코드에 비밀을 두지 않는다. 비밀은 비밀번호 하나뿐이다.
- 이 개발 환경(맥)에서는 윈도우 동작과 실제 화면 잠금을 자동으로 시험할 수 없다. 이 둘은 6-3의 수동 확인 목록으로 남긴다.

## 4. [확인] 접근 방식

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 1. 잠금 화면으로 보내기(선택) | 사이트 내용이 아예 열리지 않음. 가장 단단하고 단순함 | 다시 잠기면 쓰던 화면이 새로 열림 |
| 2. 사이트 위에 잠금 화면 덮기 | 잠겨도 쓰던 화면이 그대로 있음 | 뒤에 내용이 이미 열려 있어 덮개를 걷으면 보임 |
| 3. 섞기 | 새로 들어갈 때는 1, 열린 탭이 잠길 때는 2 | 두 방식을 다 만들어야 하고 열린 탭은 2와 똑같이 약함 |

- 사용자가 1을 골랐다. 다른 사람이 내 자리에서 보는 상황을 막는 데는 내용이 아예 열리지 않는 쪽이 맞다.

## 5. [확인] 동작 설계

5-1. 차단
- 브라우저의 요청 차단 규칙(`declarativeNetRequest` 동적 규칙)으로 지정 도메인의 페이지 요청(`main_frame`)을 확장의 잠금 화면(`lock.html`)으로 보낸다. 동적 규칙은 브라우저를 다시 켜도 남는다.
- 도메인 매칭은 `requestDomains`를 쓴다. 정규식을 직접 짜지 않는다.
- 다른 사이트에 끼워 넣은 그 사이트의 iframe(`sub_frame`)은 막기만 한다(설계자 판단, 검토 질문 2위). 잠금 화면으로 보내지 않는다.
- 사이트 권한이 빠져도 열리지 않게 한다(설계자 판단, 검토 질문 1위).
  - 잠금 화면으로 보내는 규칙은 그 사이트의 권한이 있어야 동작한다. 그런데 사용자는 툴바의 확장 메뉴에서 "사이트 액세스"를 바꾸는 것만으로 권한을 뺄 수 있다. 이 길은 확장 관리 화면을 거치지 않는다.
  - 그래서 같은 도메인에 우선순위가 더 낮은 `block` 규칙을 하나 더 둔다. `block` 규칙은 사이트 권한이 없어도 동작한다. 권한이 빠지면 잠금 화면 대신 차단 오류 화면이 뜨고, 사이트 내용은 보이지 않는다.
  - `permissions.onRemoved`로 권한이 빠진 것을 감지하면, 권한을 다시 요청하는 안내 화면을 띄운다.
  - 권한이 없을 때 `block` 규칙이 실제로 적용되는지는 동작 시험 B9로 확인한다.
- `lock.html`은 `web_accessible_resources`에 넣는다. 넣지 않으면 다른 페이지의 링크로 들어갈 때 차단 오류만 보이고 잠금 화면이 뜨지 않는다(시험 B2). 이 때문에 웹페이지가 확장 ID를 알아낼 수 있는데, 이는 감수한다.
- 잠금 화면은 원래 가려던 주소를 알고 있다가, 풀리면 그 주소로 돌아간다. 원래 주소를 넘기는 방법은 빌더가 정한다(9절).

5-2. 해제
- 비밀번호가 맞으면, 차단 규칙보다 우선순위가 높은 허용 규칙을 세션 규칙으로 넣는다. 세션 규칙은 브라우저를 끄면 사라지므로 재시작하면 자동으로 다시 잠긴다(시험 B3·B4).
- 해제 상태는 이 세션 규칙 하나로만 판단한다. 백그라운드 스크립트의 전역 변수는 스크립트가 잠들면 사라지므로 상태로 쓰지 않는다.

5-3. 다시 잠금
- `chrome.idle.setDetectionInterval(N분을 초로)`을 쓰고, `onStateChanged`가 `idle`이면 잠근다. 최소값은 15초다(시험 B8). 설정 화면에서는 1-60분 중에서 고른다.
- `onStateChanged`가 `locked`(화면 잠김)이면 바로 잠근다. 설정에서 끌 수 있다.
- 감지 간격은 백그라운드 스크립트가 시작될 때마다 다시 설정한다. 리스너는 최상위에 등록한다.
- `windows.onRemoved`에서 남은 일반 창이 없으면 잠근다. 맥에서는 창을 다 닫아도 크롬이 계속 실행되고, 윈도우도 "백그라운드 앱 계속 실행"이 켜져 있으면 마찬가지다. 그래서 세션 규칙이 남아 있다.
- 잠그기는 세션 허용 규칙을 지우고, 5-4대로 열린 탭을 처리하는 것이다.

5-4. 다시 잠길 때 열린 탭
- 지정 도메인이 열려 있는 탭마다 같은 창, 같은 위치에 잠금 화면 탭을 새로 만든다. 고정 탭 여부와 활성 여부도 그대로 옮긴다. 그런 다음 원래 탭을 닫는다.
- `tabs.update`로 주소만 바꾸면, 뒤로 가기를 눌렀을 때 브라우저 캐시(bfcache)에서 원래 화면이 그대로 다시 보인다(시험 B5 ❌). 그래서 탭을 새로 만드는 방식만 쓴다(시험 B5 ✅).
- 탭의 뒤로 가기 기록은 사라진다. 이는 감수한다.

5-5. 확장 관리 화면 보호
- `tabs.onUpdated`에서 주소가 `chrome://extensions`로 시작하고 지금 잠긴 상태이면, 그 탭을 잠금 화면으로 바꾼다. 시험에서는 바뀌기까지 약 40ms 걸렸다(시험 B7).
- 풀리면 원래 열려던 관리 화면으로 돌아간다.
- 웹스토어 정책의 "사용자가 쉽게 되돌릴 수 있어야 한다"는 조항과 부딪히지 않도록 설정에서 켜고 끌 수 있게 하고, 스토어 설명에도 이 동작을 그대로 적는다.
- 툴바 아이콘을 우클릭해 "Chrome에서 삭제"하는 것은 막을 수 없다(6-2).
- 웹스토어가 이 기능 때문에 거절하면 스토어 등록을 지킨다(사용자 답 A). 스토어 빌드에서는 이 기능을 빼고 GitHub 릴리스 빌드에만 남긴다.
  - 그래서 처음부터 이 기능을 모듈 하나로 떼어 두고, 빌드 설정 하나(예: `FMP_SETTINGS_GUARD`)로 넣고 뺄 수 있게 한다.

5-6. 비밀번호
- 해시는 WebCrypto PBKDF2-SHA256으로 만든다. 설치마다 16바이트 랜덤 salt를 쓰고, 반복 횟수는 600,000회다. 저장 형식은 `{version, salt, iterations, hash}`이다.
- 비교는 상수 시간으로 한다.
- 비밀번호는 8자 이상이어야 한다.
- 틀린 횟수를 저장한다. 5회를 넘으면 기다려야 하는 시간이 점점 늘어난다. 수치는 빌더가 정한다.
- 비밀번호를 바꾸려면 현재 비밀번호를 넣어야 한다.

5-7. 저장
- 해시 기록, 도메인 목록, 설정값, 틀린 횟수는 `chrome.storage.local`에 저장한다. 다른 기기로 퍼지지 않도록 `sync`는 쓰지 않는다.
- 해제 상태는 저장하지 않는다(5-2).

5-8. 설정 화면
- 도메인을 추가하고 지운다.
  - 입력값은 `new URL()`로 hostname만 남긴다.
  - 소문자로 바꾸고, 앞에 붙은 `*.`와 `www.`를 떼고, 국제화 도메인은 punycode로 바꾼다.
- 도메인을 추가할 때 그 도메인의 사이트 권한만 `chrome.permissions.request`로 요청한다. 사용자가 거절하면 추가하지 않는다.
- 관련 도메인을 제안한다(예: `instagram.com`을 넣으면 `instagr.am`). 제안 목록은 빌더가 정한다.
- 자동 잠금 시간(1-60분, 기본 5분), 화면이 잠기면 잠금(기본 켜짐), 확장 관리 화면 보호(기본 켜짐), 비밀번호 변경을 둔다.

5-9. 처음 설치할 때
- 설치하면 설정 화면을 열어 비밀번호를 정하게 한다. 비밀번호를 정하기 전에는 아무것도 막지 않는다.

5-10. 권한
- `declarativeNetRequest`, `storage`, `idle`, `tabs`, `alarms`(필요할 때만)
  - `declarativeNetRequestWithHostAccess`가 아니라 `declarativeNetRequest`를 쓴다. 사이트 권한 없이도 `block` 규칙이 동작해야 하기 때문이다(5-1).
  - 대가로 설치할 때 "모든 페이지의 콘텐츠 차단" 경고가 붙는다. README와 스토어 설명에 이유를 적는다.
- 사이트 권한은 `optional_host_permissions`로 두고 도메인을 추가할 때 요청한다. 잠금 화면으로 보내는 규칙에 필요하다.
- 스토어 대시보드에 권한마다 쓰는 이유를 적는다. 문구는 빌더가 초안을 쓴다.

5-11. 화면 언어
- `_locales/en`(기본)·`_locales/ko`·`_locales/ja`를 두고 `chrome.i18n`으로 바꾼다.
- README는 영어(`README.md`, GitHub 기본 표시)·한국어(`README.ko.md`)·일본어(`README.ja.md`) 세 벌이고, 맨 위의 언어 선택 줄로 오간다(사용자 지시).

## 6. [확인] 개발자 도구와 남는 빈틈

6-1. 개발자 도구(결정 C — 두 번 넘어온 질문이라 기본값으로 확정, 2026-11-13)
- 확장 자체는 개발자 도구로 푸는 것까지 막는다고 보장하지 않는다. README에 이 점을 적는다.
- 더 단단히 막고 싶은 사용자를 위해 README에 크롬 공식 관리 정책 설정을 선택 사항으로 안내한다.
  - 개발자 도구 끄기
  - 웹스토어 등록 뒤 이 확장을 강제 설치해 끄거나 지울 수 없게 하기
  - 맥(구성 프로필)과 윈도우(레지스트리) 설정 예시를 함께 둔다.

6-2. 확장으로 막을 수 없는 길(README에 적는다)
- 툴바 아이콘을 우클릭해 "Chrome에서 삭제"하기
- 크롬을 확장 끄기 옵션으로 실행하거나 프로필 파일을 직접 고치기
- 둘 다 6-1의 관리 정책으로만 막을 수 있다.
- 방문 기록(`chrome://history`), 주소창 추천, 탭 검색에는 그 사이트의 페이지 제목이 남는다.
- 그 사이트의 크롬 웹 알림(DM 미리보기 등)은 잠긴 동안에도 뜰 수 있다. v1에서는 막지 않는다(사용자 답 A). 필요하면 다음 버전에서 `contentSettings` 권한으로 다룬다.

6-3. 수동 확인 목록(자동 시험 불가)
- 맥과 윈도우에서 화면을 잠그면(`locked`) 즉시 잠기는지
- 맥과 윈도우에서 N분 동안 입력하지 않으면 잠기는지
- 맥에서 크롬 창을 모두 닫았다가 다시 열면 잠겨 있는지
- 6-1의 정책 예시가 맥과 윈도우에서 실제로 적용되는지

## 7. [확인] 기술 · 레포 · 릴리스

- 빌드는 WXT와 TypeScript로 한다. 웹스토어용 zip을 만들고, `package.json`의 버전을 매니페스트에 그대로 쓴다.
- 시험
  - 단위 시험(Vitest): 도메인 정규화, 해시 생성과 검증, 틀린 횟수 대기 시간
  - 동작 시험(Playwright와 번들 크로미움): 이번 시험 방식을 그대로 쓴다. 확장을 올리고, 테스트 도메인을 로컬로 연결하고, 같은 프로필로 다시 실행한다. 8절 B1-B7을 자동 시험으로 만든다.
- 레포: `for-my-privacy`라는 새 레포를 만든다.
- 빌드는 두 가지다. 스토어 빌드와 GitHub 릴리스 빌드이고, 둘의 차이는 5-5의 확장 관리 화면 보호 하나뿐이다. 스토어가 거절하기 전까지는 두 빌드 모두 이 기능을 넣는다.
  - `LICENSE`(MIT), `README`, `PRIVACY.md`(데이터를 밖으로 보내지 않음), `CHANGELOG.md`(Keep a Changelog 형식), `THIRD_PARTY_LICENSES`를 둔다.
- 버전: SemVer로 0.1.0부터 시작한다. `npm version`이 버전을 올리는 커밋과 `vX.Y.Z` 태그를 만든다.
- GitHub Actions
  - 태그를 push하면 빌드, 시험, zip 생성을 하고 GitHub Release에 zip을 붙인다.
  - 웹스토어 제출은 수동 실행(`workflow_dispatch`)으로만 한다.
  - 웹스토어 첫 등록은 대시보드에서 직접 하고, 그 뒤로는 웹스토어 API V2와 서비스 계정을 쓴다.
- 공개 레포를 만들 때, 처음 push할 때, 웹스토어에 제출할 때는 매번 사용자 확인을 받는다.
